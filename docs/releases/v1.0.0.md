First public release of **Better Live Coding**, a configurable, deterministic live-coding presentation extension for VS Code.

## Highlights

- Presentations defined in `.better-live-coding/presentation.json` with chapters, semantic steps and a JSON Schema.
- Ten operation types with strict text, regex and line/column anchors — a missing or ambiguous anchor stops the step.
- Deterministic Human Mode with fast (12–25 ms/char) and slow (35–60 ms/char) pace, chosen automatically for imports,
  functions and endpoints.
- Multi-file, non-linear steps with natural file switching, thinking pauses, IntelliSense and parameter hints.
- Checkpoints for every step: Skip, Restart, Restore, crash/reload recovery and unexpected-edit detection that only
  touch declared files. LF and CRLF supported; saves bypass formatters.
- Validate Presentation (full dry run + final-directory comparison), Preview Steps, Generate Checkpoints and a
  candidate-operation generator for drafting steps from two directories.
- Works offline: no telemetry, no network, never reads `.env*` files or credentials.
- Two complete examples: Basic TypeScript and Vercel Blob.

## Install

Download `better-live-coding-1.0.0.vsix` below, then:

```bash
code --install-extension better-live-coding-1.0.0.vsix
```

Requires VS Code 1.90 or newer.

## Known limitations

- Typing uses direct edits, so editor auto-closing, auto-indent and snippets are not applied (output equals the configured text).
- IntelliSense content depends on the installed language extensions; it is displayed, never relied on.
- A presentation edits files inside one workspace folder; multi-root presentations are not supported.
- Real keyboard behaviour (Enter in the terminal and widgets) should be checked manually before a talk — see `docs/manual-verification.md`.
